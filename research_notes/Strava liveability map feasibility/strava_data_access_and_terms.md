# Strava data access routes and their terms (as of October 2026)

Scope note: this covers every route by which a third-party website could obtain aggregate "where people run/ride" data from Strava, the governing legal documents (with version dates), and enforcement history. Throughout, **"technically possible"** and **"contractually permitted"** are flagged separately. Legal documents cited and their version dates as fetched on 2026-10-17:

## Key Question 1: Strava API v3 — endpoints, aggregate/heatmap data, rate limits, approval process

### Takeaway
The API exposes per-athlete activities, streams, routes and segment metadata (including `athlete_count`/`effort_count` on segments) but no heatmap or aggregate endpoint of any kind; the only "discovery" endpoint, Explore Segments, was restricted to approved Extended Access Tier apps on September 1, 2026. Since June 1, 2026 a paid Strava subscription is required to hold a Standard-tier API app, new apps are capped at 1 athlete (self-upgrade to 10), and anything larger needs a case-by-case review that Strava says is "not a guarantee."

### Cited Findings

**Endpoints**
- Endpoint families in the v3 reference: Segments (Explore Segments, List Starred Segments, Get Segment, Star Segment); SegmentEfforts (List Segment Efforts, Get Segment Effort); Streams (Get Activity Streams, Get Route Streams, Get Segment Effort Streams, Get Segment Streams); Routes (Export Route GPX/TCX, Get Route, List Athlete Routes); Activities (Create, Get, List Comments, List Kudoers, List Laps, List Athlete Activities, Get Activity Zones, Update). No heatmap or aggregate endpoint appears in the index. — [Strava API v3 Reference](https://developers.strava.com/docs/reference/)
- Explore Segments (`GET /segments/explore`) takes `bounds` (SW/NE lat-lng), `activity_type` (running or riding), `min_cat`/`max_cat`; returns the top 10 matching segments; documented as "Limited to Extended Access Tier apps with granted permission." Response includes id, name, climb category, average grade, start/end coordinates, elevation difference, distance, encoded polyline. — [Strava API v3 Reference](https://developers.strava.com/docs/reference/)
- Get Segment (`GET /segments/{id}`) returns `effort_count`, `athlete_count`, `star_count`, `athlete_segment_stats`, `total_elevation_gain`; requires `read_all` scope for private segments. List Segment Efforts and Get Segment Effort "require a subscription." — [Strava API v3 Reference](https://developers.strava.com/docs/reference/)
- Activity endpoints require `activity:read` for Everyone/Followers activities and `activity:read_all` for Only-Me activities; List Athlete Activities filters out Only-Me unless `read_all`; Get Athlete Stats "includes only activities set to Everyone visibility." — [Strava API v3 Reference](https://developers.strava.com/docs/reference/)
- Changelog, June 1, 2026: "Introduction of new deauthorization endpoint"; "Expose application tier in API Settings Dashboard"; "Introduction of self service expanded access in API Settings Dashboard for single player developers"; Club Activities/Members/Admins endpoints and Explore Segments restriction announced for September 1, 2026; base URL changing from `https://www.strava.com/api/v3` to `https://api-v3.strava.com` (available January 4, 2027). Changelog, September 1, 2026: "Club Activities, Club Members, and Club Admins endpoints removed"; "Explore Segments endpoint restricted to approved Extended Access Tier developers." — [Strava V3 API Changelog](https://developers.strava.com/docs/changelog/)
- Segment leaderboard endpoint was removed from the API after a 30-day migration period ending June 18, 2020; "Segment Effort & Leaderboard data, included fields such as kom_rank, are only available for subscribers." — [Strava segment-changes page](https://developers.strava.com/docs/segment-changes/); contemporaneous coverage: [DC Rainmaker, May 2020](https://dcrainmaker.com/2020/05/strava-leaderboard-reduces.html)

**Rate limits**
- Default per-app limits: overall 200 requests / 15 min and 2,000 / day; non-upload (read) 100 / 15 min and 1,000 / day. 15-minute windows reset at :00/:15/:30/:45; daily resets at midnight UTC; over-limit returns HTTP 429; headers `X-RateLimit-Limit/Usage` and `X-ReadRateLimit-Limit/Usage`. — [Rate Limits](https://developers.strava.com/docs/rate-limits/)
- Self-service upgraded limits (via API Settings Dashboard): overall 400 / 15 min and 4,000 / day; read 200 / 15 min and 2,000 / day; athlete capacity 10. — [Rate Limits](https://developers.strava.com/docs/rate-limits/)
- To request higher limits: increases "are only considered for apps nearing their capacity"; review the API Agreement; follow brand guidelines; submit the Developer Program form with screenshots of everywhere Strava data appears and of the "Connect with Strava" button; increased access is "not a guarantee." — [Rate Limits](https://developers.strava.com/docs/rate-limits/)

**Approval process / athlete caps / subscription**
- "All new applications start in single-player mode," limited to the developer's own account; "A Strava subscription is required to create an app." Upgrade in the dashboard raises capacity to 10 athletes; beyond that the app must be submitted for review. — [Getting Started](https://developers.strava.com/docs/getting-started/)
- Strava FAQ: "A Strava subscription is a prerequisite" for building with the API; tiers: Single User = 1 athlete; Standard = up to 9,999 athletes (self-upgrade to 10 without review); Extended Access = 10,000+; "there is no additional fee" beyond the subscription; apps are reviewed case by case for whether they "complement the Strava experience, meet our quality bar" and handle data under the Agreement/Policy; "increased access is not a guarantee." — [Strava API FAQ (Community Hub)](https://communityhub.strava.com/developers-knowledge-base-14/strava-api-faq-12906)
- Official June 1, 2026 announcement ("An Update To Our Developer Program", posted by Strava community manager Elliott): "Starting today, all current and future applications will automatically receive access to the Standard developer tier"; "A Strava subscription will be required to access the API as a Standard Tier developer" from June 1, 2026 for new developers and June 30, 2026 for existing ones; active developers (any API request in 2026) without a subscription got a 3-month free code; "Extended Access Tier developers are not affected"; Extended Access brings "prioritized developer support, higher rate limits, greater user capacity" with "no Strava subscription required." Rationale cited: developer applications "up 448% year-to-date," "AI companies are aggressively attempting to scrape platforms for training data," zero-code AI tools "that produce apps that hammer APIs," and "serious patterns of abuse." — [Strava Community Hub](https://communityhub.strava.com/insider-journal-9/an-update-to-our-developer-program-13428)
- API Policy §3.3: Extended Access Tier is "generally inclusive of Developer Applications serving 10,000 users or more and approved by Strava... admitted on a case-by-case basis and are not subject to subscription requirements"; "Standard Tier Applications are subject to subscription requirements as published on the Strava developer site, including a requirement that the developer or specified end users maintain an active Strava subscription." — [API Policy](https://www.strava.com/legal/api_policy)
- Third-party reporting of the subscription price: US$11.99/month or US$79.99/year, with Strava quoted as saying >240,000 developers are affected. — [heise.de](https://heise.de/-11315017); [Sahha blog](https://sahha.ai/blog/strava-api-changes-2026/) (secondary sources; the price is not stated on Strava's developer pages fetched)
- API Agreement §3.2 (still present in the June 2026 text despite the subscription requirement): "Access to and use of the Strava API Materials and the Strava Platform are currently provided at no charge. Strava reserves the right to charge you... including, without limitation, rated pricing and/or differentiated pricing for business users." — [API Agreement](https://www.strava.com/legal/api)

### Inferences
- Technically, the only ways to approximate "where people run most" from the API are (a) Explore Segments' top-10-per-bounding-box list plus each segment's `athlete_count`/`effort_count` (now Extended-Access-only), or (b) pulling `latlng` streams from many consenting athletes and rasterising them yourself. Route (b) is throttled to 1,000 read calls/day by default and 1 athlete until review, and is contractually barred (see Q2).
- A hobbyist public website cannot realistically pass the Extended Access bar (10,000+ users, case-by-case approval) that is now a precondition for the one discovery endpoint.

### Gaps
- The full list of stream types in the reference page was truncated in my fetch; `latlng`, `distance`, `altitude` confirmed, others (time, heartrate, etc.) not re-verified here.
- Strava publishes no review timeline or acceptance rate for the "submit for review" step.
- The subscription price is only confirmed via secondary press; Strava's own developer pages say "no additional fee" without a figure.

## Key Question 2: Strava API Agreement / API Policy — prohibitions (verbatim)

### Takeaway
The June 1, 2026 API Agreement and its incorporated API Policy prohibit, in express terms, every element of a public "where people run" site built on API data: showing one user's data to anyone else (even public data), aggregating/anonymising/analysing it, building datasets or persistent stores, caching beyond 7 days, storing geographic information, AI/ML use of any kind (including RAG and context-window ingestion), look-alike apps, and transfer to third parties even with user consent.

### Cited Findings

**Display to other users**
- API Agreement highlights: "Strava Data provided by a specific user can only be displayed or disclosed in your Developer Application to that user. Strava Data related to other users, even if such data is publicly viewable on the Strava Platform, may not be displayed or disclosed." — [API Agreement, eff. June 1, 2026](https://www.strava.com/legal/api)
- API Policy §2.3 "Display Limited to the Authenticated User": "Strava Data provided by a specific Strava user may be displayed or disclosed in your Developer Application only to that user. You may not display or disclose Strava Data related to other users, even if such data is publicly viewable on the Strava Platform." — [API Policy, eff. June 1, 2026](https://www.strava.com/legal/api_policy)
- API Policy §6.1 "Scope of Data Access": "Unless your Developer Application has an athlete capacity of 9,999 or less, you may display or disclose to an end user only the specific Strava Data related to that end user. You may not display or disclose Strava Data related to other users, even if such data is publicly viewable on the Strava Platform." (Note the odd drafting of the first sentence; the second sentence is unconditional.) — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §7.1: "If your Developer Application does not collect the authentication credentials of a Strava user, you are not permitted to display any data or use any functionality via the Strava API Materials relating to that user." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §5.13 (consent): "You may not use the Strava API Materials in any way that would grant anyone other than you or the applicable Strava user the right to see data related to that user without the prior express consent of that user." — [API Policy](https://www.strava.com/legal/api_policy)
- Strava's own Nov 2024 framing named heatmaps explicitly: the display rule exists to stop data being shown to others "for example, in a public feed or heatmap." — [Strava Press, Nov 15/19, 2024](https://press.strava.com/articles/updates-to-stravas-api-agreement)

**AI / ML**
- API Policy §5.3 "No AI/ML Training, Fine-Tuning, Grounding, Evaluation, Embedding, or Retrieval-Augmented Generation": "You may not use the Strava API Materials or Strava Data, directly or indirectly, in connection with the development, training, evaluation, or operation of any AI Application. This prohibition extends to: Any data derived from, aggregated from, anonymized from, or generated using Strava Data, in any form (including original, derivative, aggregated, anonymized, de-identified, or model-output form); and Any of the following activities with respect to an AI Application: training, pre-training, post-training, fine-tuning, reinforcement learning, alignment, grounding, evaluation, benchmarking, embedding generation, retrieval-augmented generation, ingestion into a context window or working memory, and any other activity intended or reasonably likely to develop, improve, evaluate, or operate an AI Application. This prohibition does not extend to use of the Strava MCP, as discussed above in Section 3.5." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §3.5 "Strava MCP": the Strava MCP "is the sole authorized first-party agent-mediated interface... Subscribers to Strava may access the Strava MCP in connection with their personal use of their own Strava data... The Strava MCP is not authorized for, and may not be used to enable, any commercial or third-party access to the Strava API Materials or Strava Data outside the developer's own personal use." — [API Policy](https://www.strava.com/legal/api_policy)
- The Nov 2024 Agreement first added language to "explicitly prohibit third parties from using any data obtained via Strava's API in artificial intelligence models." — [Strava Press](https://press.strava.com/articles/updates-to-stravas-api-agreement)
- FAQ: apps that "expose athlete data to third party AI tools" will not be approved. — [Strava API FAQ](https://communityhub.strava.com/developers-knowledge-base-14/strava-api-faq-12906)

**Replicating Strava features / look-alike**
- API Agreement highlights: "You may not create applications that compete with or replicate Strava functionality." — [API Agreement](https://www.strava.com/legal/api)
- API Policy §5.2 "No Competing or Imitating Applications; No Benchmarking": "You may not use the Strava API Materials in any manner that is competitive to Strava or the Strava Platform, including in connection with any application, website, or other product or service that includes, features, endorses, or otherwise supports a third party that provides services competitive to Strava's products and services. You may not use the Strava API Materials to create an application that imitates the look, imagery, or brand identity of Strava or the Strava Platform. You may not use or access the Strava API Materials to monitor the availability, performance, or functionality of the Strava Platform or for any other benchmarking or competitive analysis purpose." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §5.6: you may not "Frame, wrap, or otherwise reproduce significant portions of the Strava Platform" or "Modify or create derivative works based upon the Strava API Materials or distribute copies of them." — [API Policy](https://www.strava.com/legal/api_policy)
- Nov 2024: "Additional terms have been added to protect Strava's unique look and feel and functionality." — [Strava Press](https://press.strava.com/articles/updates-to-stravas-api-agreement)

**Aggregation, datasets, analytics, geographic storage**
- API Policy §5.4 "No Aggregation, Analytics, or De-Identified Processing": "You may not process or disclose Strava Data—even publicly viewable Strava Data—including in an aggregated, de-identified, or anonymized manner, for the purposes of analytics, analyses, customer insight generation, or product or service improvements. You may not combine Strava Data with other customer data for these or any other purposes. The restrictions in this Section 5.4 apply to data derived from Strava Data and to output that incorporates or was generated using Strava Data." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §5.5 "No Scraping, Bulk Export, Harvesting, or Automated Extraction": "You may not use web scraping, web harvesting, web data extraction methods, or any other automated means to extract data from the Strava Platform. You may not bulk-export Strava Data, including by accumulating Strava Data through repeated authorized API calls into a corpus, dataset, archive, or database that exceeds the operational scope of your Developer Application. You may not store Strava Data, or any data derived from Strava Data, in any Persistent Index. The foregoing prohibits indefinite storage in vector stores, embedding stores, search indexes, knowledge graphs, retrieval-augmented data stores, archives, and any other storage configured to enable subsequent retrieval, query, or use." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §5.7 "No Aggregating, Caching, or Storing User or Geographic Information": "You may not use or access the Strava API Materials to aggregate, cache, or store geographic location information or other user information accessible via the Strava API, except as expressly permitted by Section 6.2." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §6.2 "Cache and Retention": "You may not retain Strava Data in your cache for longer than seven (7) days. If your Developer Application checks for a resource (for example, a segment) and that resource is no longer available from Strava, you must remove it from your cache immediately... Except for such limited caching, you may not store Strava Data, or provide or display Strava Data or any associated service, to any third party other than the Strava user using your Developer Application." §6.3: deletions must be reflected "within forty-eight (48) hours." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §3.2 reserves the right to restrict "endpoints that expose aggregated user data, social-engagement data products, or other proprietary content" and to maintain an allowlist; developers wanting to "exceed published limitations" are told to email developers@strava.com. — [API Policy](https://www.strava.com/legal/api_policy)

**Third-party sharing / sale / intermediaries / charging**
- API Policy §5.10 "No Sale, License, or Transfer to Third Parties": "You may not transfer or disclose Strava Data — including publicly viewable Strava Data — to any third party, except as expressly permitted... You may not, directly or indirectly, disclose, market, sell, license, lease, or make available in exchange for monetary or other valuable consideration, any Strava Data to any third party — including advertisers, data brokers, AI Application providers, or model developers — even if a user of your Developer Application consents." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §5.8: "You may not charge end users, in any manner, for access to or use of the Strava API Materials or any services or functionality included in or related to the Strava API Materials or the Strava Platform... The foregoing does not prohibit you from charging for the provision of functionality not provided by the Strava Platform... and that is not substantially duplicative of functionality offered by Strava." §5.9: ads allowed but "you may not use Strava Data in any advertisement without Strava's express written consent" and no "targeted advertising." — [API Policy](https://www.strava.com/legal/api_policy)
- API Policy §5.16 "No Abstraction Layers, Pass-Through Proxies, or Unauthorized Agent Interfaces": bans operating "any abstraction layer, integration-platform-as-a-service, no-code-AI platform, pass-through proxy, intermediary, or aggregator that re-exposes the Strava API Materials," "any MCP Server, agent-mediated interface, or analogous mechanism," token sharing/multiplexing, and any app "whose primary purpose is to enable third parties to access the Strava API Materials or Strava Data through your credentials or infrastructure." — [API Policy](https://www.strava.com/legal/api_policy)
- June 2026 announcement: "Apps routing Strava data through third-party intermediary platforms are no longer supported" because they "prevent us from verifying how athlete data is being accessed and used downstream." — [Strava Community Hub](https://communityhub.strava.com/insider-journal-9/an-update-to-our-developer-program-13428)

**Enforcement mechanics in the Agreement**
- API Agreement §2.2: Strava may "revoke your API Token or terminate or limit any uses... if you violate this Agreement or we otherwise object to your use." §4.2: termination "immediately" for non-compliance or any activity "that may expose Strava to risk or liability." §6.2: Strava "shall be entitled to inspect and audit your Developer Applications." §9.1: Strava retains "all worldwide right, title and interest in and to... Strava Data." — [API Agreement](https://www.strava.com/legal/api)
- Highlights: "Use of Strava's API is a privilege granted to you by Strava, not a right. Strava may modify or discontinue access to the Strava API at any time for any reason." — [API Agreement](https://www.strava.com/legal/api)

### Inferences
- Contractually, an API-based public heatmap/popularity map is barred under at least five independent clauses (§2.3/§6.1 display, §5.4 aggregation, §5.5 dataset accumulation, §5.7 geographic storage, §6.2 7-day cache). There is no consent-based carve-out for the display or aggregation rules in the 2026 Policy; §5.10 explicitly says user consent does not cure third-party transfer.
- The §3.2 allowlist/"contact developers@strava.com" route is the only written path to an exception, and the stated basis is "the value those Developer Applications provide to Strava users" — a liveability website serving non-Strava-users does not fit that description.

### Gaps
- No text found explaining the conditional phrasing of §6.1 ("Unless your Developer Application has an athlete capacity of 9,999 or less"); whether Strava intends a different rule for small apps is unclear and §2.3 applies regardless.
- No published record of Strava granting an allowlist exception for aggregate/geographic display.

## Key Question 3: Strava Global Heatmap — viewability, ToS on scraping/embedding, reverse-engineered tiles, OSM agreement

### Takeaway
Since March 2018 street-level heatmap detail requires a (free) Strava login; low-zoom tiles are technically fetchable but high-zoom tiles require signed CloudFront cookies, and as of March 2025 Strava added further protections that broke direct TMS URLs. The Terms of Service (eff. Sept 28, 2026) prohibit any automated collection "regardless of whether you are logged into a Strava account," and the only known permission is an informal, repeatedly-questioned grant to the OSM community for tracing into OSM only — Strava's own wiki text directs any other use to Strava Metro.

### Cited Findings

**Login/zoom gating history**
- January 2018: the public heatmap (about one billion activities through September 2017, 3 trillion lat/lng points) was found to reveal military installations. — [CNBC, Jan 28, 2018](https://www.cnbc.com/2018/01/28/global-heat-map-for-joggers-exposing-sensitive-us-military-information.html)
- March 2018: Strava said it would "restrict access to street-level details to anyone who isn't a registered user"; low-traffic roads stay hidden until "enough users submit workouts in the area"; map "refreshed monthly to wipe off data that people make private." — [Engadget, Mar 13, 2018](https://www.engadget.com/2018/03/13/after-exposing-secret-military-bases-strava-restricts-data-visi/); [CNN Money, Mar 13, 2018](https://money.cnn.com/2018/03/13/technology/strava-privacy-update-settings) (CNN noted anyone can sign up for a free account to regain street-level view)
- March 15, 2018: OSM mailing list reports JOSM heatmap layers failing with "HTTP error 403 when loading tiles." — [OSM-talk](https://lists.openstreetmap.org/pipermail/talk/2018-March/080374.html)
- Strava Support (current): the Global Heatmap "shows activity from the past year and updates monthly"; excludes activities not set to "Everyone," portions hidden by map-visibility settings, and users who opted out; "We do not show 'heat' in an area until multiple users have uploaded activities traversing that area in the last year." No permitted-use or embedding statement. — [Strava Support: Global Heatmap](https://support.strava.com/hc/en-us/articles/216918877-Strava-Global-Heatmap)
- November 13, 2024: Strava added Night (sunset-to-sunrise) and Weekly (past 7 days) heatmaps; Global heatmap remains available to "all users," while Night, Weekly and Personal heatmaps are subscriber-only; public heatmaps use "de-identified and aggregated data" from "Everyone"-visibility activities. — [Strava Press](https://press.strava.com/articles/strava-expands-mapping-tools-with-night-and-weekly-heatmaps)

**Terms of Service on scraping / automated access / aggregated data (eff. Sept 28, 2026)**
- "You agree not to access the Services by any means other than through the interfaces that are provided by Strava. You are prohibited from accessing any data on the Services that you are not expressly authorized to access. Automated access to or collection of data from the Services—by any means, including data mining, robots, screen scraping, scripts, or similar data-gathering tools or software such as browser extensions and crawlers—is prohibited. This prohibition applies regardless of whether you are logged into a Strava account at the time of such automated access or collection." — [Strava Terms of Service](https://www.strava.com/legal/terms)
- "You acknowledge and agree that the Services, any software used in connection with the Services, any aggregated data based on Content on the Services, and any Content... contain proprietary and confidential information that is protected by relevant intellectual property and other laws... you agree not to modify, rent, lease, loan, sell, distribute, or create derivative works based on the Services, the software, or Content available on the Services." Only "a limited, non-exclusive right to create a text hyperlink to the Services" is granted; framing is not mentioned. — [Strava Terms of Service](https://www.strava.com/legal/terms)

**Reverse-engineered tile URLs (technical reality)**
- OSM wiki documents the tile pattern `https://heatmap-external-{a,b,c}.strava.com/tiles-auth/{ACTIVITY}/{COLOR}/{zoom}/{x}/{y}.png?Key-Pair-Id=…&Policy=…&Signature=…` where the three values come from the logged-in browser's `CloudFront-Key-Pair-Id`, `CloudFront-Policy`, `CloudFront-Signature` cookies; ACTIVITY ∈ {run, ride, winter, water, all}; COLOR ∈ {blue, bluered, purple, hot, gray}; cookies expire in about one week. A low-resolution unauthenticated layer (`/tiles/...`) is bundled in JOSM's imagery list but "is not detailed enough for tracing." Tools listed: Python URL builders, browser extensions for JOSM and iD, a userscript, and proxies. — [OSM Wiki: Strava](https://wiki.openstreetmap.org/wiki/Strava)
- OSM wiki history: "Late March 2025: Strava deployed new URLs with extra security. TMS URLs stopped working without a proxy"; manual JOSM process marked not working 22 June 2025; JOSM browser extension non-functional May–September 2026 and reported fixed October 2026; page last edited 3 October 2026. — [OSM Wiki: Strava](https://wiki.openstreetmap.org/wiki/Strava)
- My own probe on 2026-10-17 (technical, not a source): anonymous `GET heatmap-external-a.strava.com/tiles/all/hot/13/4000/2800.png` returned HTTP 403; the same path under `/tiles-auth/` without cookies returned HTTP 403; a z11 `/tiles/` request returned 404 (likely an empty/out-of-coverage tile rather than a permission error). This is consistent with the wiki's description that high zoom requires signed cookies.
- Nov 2024 DC Rainmaker coverage lists VeloViewer's "heatmap tiles" among features hit by the display rule — i.e., third-party heatmap tiles built from API data were an existing practice that the 2024 Agreement shut down. — [DC Rainmaker, Nov 19, 2024](https://dcrainmaker.com/2024/11/stravas-changes-to-kill-off-apps.html)

**OSM community permission — exact scope**
- OSM wiki: "OSM users have permission, reconfirmed in November 2019, to use the heatmap data for tracing into OSM only. For other non-personal uses, including tracing into other datasets, the page says to contact Strava Metro." The wiki also warns heat lines do not imply public access rights. — [OSM Wiki: Strava](https://wiki.openstreetmap.org/wiki/Strava)
- OSM community thread "Strava: mapping legal usage" (Dec 21–22, 2022): DWG member Elliott Plack considers use fine based on the permission Strava gave; Simon Poole calls the permission "hand wavy," notes it could end at any time, that the real issue is circumventing access protections, and that individual contributors are "on your own"; the permission is traced to a message from a Strava product manager discussed in iD issue #9129 and it is unclear whether it covers the whole community; the only Strava text quoted is "only registered Strava athletes may zoom in to street-level details"; no Strava statement explicitly permits the tiles-auth/cookie workaround; the extension author (Zeke Farwell) notes Strava "could block external origins if it wanted to." — [OSM Community Forum](https://community.openstreetmap.org/t/strava-mapping-legal-usage/7104)

### Inferences
- Technically possible: with a logged-in (free) account, a script can harvest weekly-rotating signed cookies and pull full-resolution PNG heat tiles, and the OSM community has maintained working tooling for this through 2026 despite repeated breakages. Contractually: the ToS bans exactly this ("scripts... browser extensions and crawlers... regardless of whether you are logged in"), and the OSM permission is (a) informal, (b) limited to tracing vectors into OSM, and (c) explicitly excludes other uses, which the wiki redirects to Strava Metro. Re-hosting, embedding, or deriving a public "popularity" layer from heatmap tiles falls outside the only known permission.
- Strava's March 2025 URL hardening and the Sept 2026 ToS language ("regardless of whether you are logged into a Strava account") show active, escalating intent to block tile harvesting even by account holders.

### Gaps
- I found no public cease-and-desist or lawsuit by Strava specifically over heatmap tile scraping; absence of evidence, not evidence of tolerance. The OSM thread's "wait for a DMCA" framing suggests none has been issued to OSM mappers as of late 2022.
- No Strava document states a numeric minimum-user threshold for showing heat ("multiple users" only).
- I could not confirm the current maximum zoom served to logged-out users (a 2018 OSM post cited zoom 12 per the search snippet, but the fetched message did not contain it).

## Key Question 4: Strava Metro — eligibility, cost, granularity, licence, hobbyist/commercial eligibility

### Takeaway
Metro is free (since September 2020) but only for organisations that "plan, own, or maintain active transportation or outdoor recreation infrastructure" or seek to influence such planning, plus vetted consultants, accredited academics, and tourism bodies; Strava expressly refuses real-estate investors, financial-services firms and retailers. The Metro Terms (Sept 4, 2026) confine use to the single approved project, forbid public distribution of the underlying data (including Edge Counts), require 30-day pre-publication review of any external report, and ban commercial exploitation and AI use — a public liveability website is not a permitted output.

### Cited Findings

**Eligibility and cost**
- Metro Terms §2.1.1: "Strava Metro is available to organizations that plan, own, or maintain active transportation or outdoor recreation infrastructure, or that seek to positively influence active transportation or outdoor recreation planning processes, and whose intended use falls within a Project Type approved by Strava in its sole discretion." — [Strava Metro Terms, last updated Sept 4, 2026](https://metro.strava.com/terms)
- Metro FAQ: qualifying partners are public agencies (DOTs, planning organisations, trail organisations, cities) and organisations seeking to influence planning; "Strava doesn't partner with real estate investors, financial services companies, or retailers." — [Strava Metro FAQ](https://metro.strava.com/faq)
- Metro Terms §5 "Fees": "Strava provides the Strava Metro Service to Licensees on a no-cost basis, but reserves the right to charge fees at any time." Homepage: "access to Strava Metro is free of charge." — [Metro Terms](https://metro.strava.com/terms); [metro.strava.com](https://metro.strava.com/)
- Metro became free September 2020; since 2014 partners had paid an annual fee. — [Bicycle Retailer, Sept 23, 2020](https://bicycleretailer.com/industry-news/2020/09/23/strava-metro-now-free-urban-planners-and-advocates); [endurance.biz](https://endurance.biz/2020/industry-news/strava-metro-now-free-for-urban-planners-around-the-world/). Pre-2020 example pricing: Conway, Arkansas 2016 resolution for an annual Strava Metro contract at $1,800. — [City of Conway R-16-38](https://media.conwayarkansas.gov/media/archive/resolutions/2016/R-16-38.pdf)
- Consultants (§2.4) may access only "under a formal written contract by a Licensee in good standing," limited to the partner's Territory and Project Type, project-by-project, non-transferable. — [Metro Terms](https://metro.strava.com/terms)
- Academic Program (§2.5): "only to qualifying academic researchers affiliated with an accredited institution of higher education, and only for non-commercial academic research"; "outputs of academic research may not be transferred to any commercial party without Strava's prior written consent." 2027 cohort applications close October 23, 2026; one year of access; selected by a Strava committee. — [Metro Terms](https://metro.strava.com/terms); [Metro Academics](https://metro.strava.com/academics)
- Tourism Use Case (§2.6): applicants limited to destination-management organisations, government tourism authorities, nonprofits and their consultants; tourism data "may not be exported in any form (including via the Edge Counts feature)" unless Strava enables it. — [Metro Terms](https://metro.strava.com/terms)

**Granularity**
- Metro FAQ: data covers run, walk and bike trips over time; insights by time of year, day of week, time of day, before/after infrastructure; areas of interest defined by county; shapefile/GIS exports available; "Heat isn't shown in an area until multiple users have uploaded activities traversing it in the past year"; excludes private/non-"Everyone" activities, hidden map segments, deleted accounts and opt-outs; user base "doesn't equally represent all genders and ages." — [Strava Metro FAQ](https://metro.strava.com/faq)
- Metro help centre article titles include "Hexagon Counts," "Hexagon Counts - Data Export and Download," "Travel Times," "Commutes in Metroview," "Glossary & Data Dictionary," "How Strava Metro protects user privacy." — [Strava Metro Help Center](https://stravametro.zendesk.com/hc/en-us)
- Commutes are identified both from user tags and Strava's pattern-based classifier; commute totals appear "as a field in the Edge Counts export for partners"; filters by mode, date range, time of day, day of week. — [Commutes in Metroview](https://stravametro.zendesk.com/hc/en-us/articles/360045856354-Commutes-in-Metroview)
- Metro Terms §2.6 and §2.7.2 confirm an "Edge Counts feature" (exportable for standard partners) and non-exportable "Counter Data." — [Metro Terms](https://metro.strava.com/terms)
- Independent description of a 2017 Metro delivery (Sheffield, via Glasgow Urban Big Data Centre): "an hourly count of users at street level and wait times at intersections based on the Open Street Map roads network"; origins/destinations "resolved to census output areas"; binning "0 if this number is less than or equal to 3, otherwise rounded up in multiples of 5." — [UBDC / University of Glasgow](https://researchdata.gla.ac.uk/1916/)
- NYSDOT description: Strava data tied to OSM segments, available as hourly/daily/monthly/yearly aggregates; monthly refresh gives hourly counts, yearly gives monthly counts; access restricted to authorised agency staff and contractors. — [511NY Rideshare analytics sandbox](https://511nyrideshare.org/web/analytics-sandbox-for-emerging-mobility-data-sources/strava) (page body did not render in my fetch; detail comes from the search snippet)
- Demographics: Metro provides summary age/sex of users but "these details are not included in the underlying activity data," so trips cannot be tied to a demographic group (Bath Hacked analysis); a Colorado DOT 2018 analysis includes an age/gender table of unique users. — [Bath Hacked](https://bathhacked.org/projects/bath-cycling/strava-metro-first-steps); [CDOT Strava Analysis Summary, June 2018](https://www.codot.gov/programs/bikeped/documents/strava-analysis-summary_06-25-18.pdf/@@download/file/Strava%20Analysis%20Summary_06.25.18.pdf)

**Licence restrictions (verbatim, Metro Terms, Sept 4, 2026)**
- Highlights: "Do not share, redistribute, resell, or publicly post the underlying Strava Data. You may share Licensee Reports that comply with these Metro Terms." "You may not use Strava Data to train, fine-tune, evaluate, or benchmark machine-learning or AI systems, ingest Strava Data into any AI or machine-learning system to generate reports, summaries, or other output, or use Strava Data to develop competitive products." — [Metro Terms](https://metro.strava.com/terms)
- §2.1.2: rights are "limited, revocable, non-exclusive, non-transferable, non-sublicensable" and "solely to evaluate the Strava Data and prepare Licensee Reports solely for the specific Project Type identified in Licensee's application." — [Metro Terms](https://metro.strava.com/terms)
- §2.2.2: "THIRTY (30) DAYS PRIOR to any publication of a Licensee Report outside of Licensee's organization, Licensee shall submit for Strava's review and approval a copy of the Licensee Report. If, in Strava's sole discretion, the Licensee Report... damages Strava's reputation, brand, or goodwill... Licensee shall revise." — [Metro Terms](https://metro.strava.com/terms)
- §2.2.3 "NO SHARING OF STRAVA DATA": Licensee "shall not publicly distribute any Strava Data downloaded from the Strava Metro Service, including the underlying raw counts in the Strava Data, except as permitted in Licensee Reports"; screenshots "may be shared for the limited purpose of supporting active transportation and Tourism Use Cases only, such as grant applications, initiatives for community bike lanes, or destination-management planning"; Strava may demand removal of any public post containing screenshots "for any reason." — [Metro Terms](https://metro.strava.com/terms)
- §2.2.4: Licensee may "reproduce, publicly display, and distribute the Licensee Reports solely in connection with the relevant Project Type" but shall not "access, use, reproduce, disclose, publicly display or perform, commercially exploit, reverse engineer, prepare derivative works of, distribute, or sublicense the Strava Data other than for the Project Type." — [Metro Terms](https://metro.strava.com/terms)
- §2.2.1(d): every Licensee Report must carry: "This report includes aggregated and de-identified data from Strava Metro." §2.2.1(b): combination with third-party data allowed but not for benchmarking/comparison except validation. — [Metro Terms](https://metro.strava.com/terms)
- §2.3: no use for "competitive analysis" and no attempt to "directly or indirectly identify a Strava member." §6.2: on termination, destroy all Strava Data; reports prepared before termination may continue to be displayed. — [Metro Terms](https://metro.strava.com/terms)

### Inferences
- A hobbyist individual cannot be a Licensee (Authorized Users must be "an individual employee of the Licensee"); a commercial company could only enter as a Consultant under contract to an existing public-agency partner, for that partner's project and territory.
- Even a qualifying partner could not lawfully power a public, continuously-updated map website from Metro: the underlying counts/Edge Counts cannot be publicly distributed, screenshots are limited to advocacy/grant/tourism contexts, and every external publication needs 30-day pre-approval. A "liveability signal" product is closer to the excluded real-estate/retail use cases than to transportation planning.

### Gaps
- Strava's own current data dictionary (hexagon size, edge-count rounding, demographic bins) sits behind the Metro help centre login; the only concrete binning rule found (≤3 → 0, else round up to multiples of 5) is from a 2017 dataset and may have changed.
- No source confirms whether Strava would consider a non-profit "liveability" or walkability advocacy group as "seek[ing] to positively influence active transportation... planning processes."

## Key Question 5: Enforcement history

### Takeaway
Strava's pattern is to enforce by contract and platform controls rather than by litigation against developers: leaderboard removal (2020), Flyby opt-in (2020), the November 2024 display/AI/analytics clauses that forced VeloViewer, Intervals.icu, CityStrides and others to hide shared data within ~30 days, and the June 2026 subscription paywall plus endpoint removals. The only lawsuit found is Strava v. Garmin (filed Sept 30/Oct 2, 2025, D. Colo.), which asserts Strava's own heatmap and segment patents — a signal that Strava treats heatmaps as protected IP.

### Cited Findings
- **May–June 2020:** segment leaderboard endpoint removed from the API after a 30-day migration ending June 18, 2020; segment effort/leaderboard fields limited to subscribers. — [developers.strava.com/docs/segment-changes](https://developers.strava.com/docs/segment-changes/); [DC Rainmaker](https://dcrainmaker.com/2020/05/strava-leaderboard-reduces.html). Cycling Weekly reported Strava said the change protected privacy but also maintained the app's "unique" feel and appearance. — [Cycling Weekly](https://cyclingweekly.com/news/strava-blocks-other-apps-from-using-leaderboard-and-segment-data)
- **October 2020:** after a stalking controversy, Flyby was made opt-in ("default off"). — [PisteHors, Oct 16, 2020](https://pistehors.com/9LBtMXUByuHDGsGAaXEE/strava-kills-stalking-feature)
- **November 2024:** Agreement changes effective Nov 11; developers emailed Nov 18 with roughly 30 days' notice; the three clauses quoted: "Third-party apps are no longer able to display your Strava activity data on their surfaces to other users"; prohibition on use "in artificial intelligence models or other similar applications"; "You may not process or disclose Strava Data… for the purposes of, including but not limited to, analytics, analyses…". Affected: VeloViewer (segment lists, Zwift leaderboards, challenges, other users' efforts, heatmap tiles), Intervals.icu (hid historical Strava data from coaches, later retained coach access but lost follower visibility), Final Surge, Xert, TrainerRoad (AI clause). Reader-reported: Wandrer.earth struggling; Statshunters received a "no action required" notice. — [DC Rainmaker, Nov 19, 2024](https://dcrainmaker.com/2024/11/stravas-changes-to-kill-off-apps.html)
- Strava's Nov 2024 statement: changes affect "less than .1%" of applications; coaching platforms "focused on providing feedback to users" remain allowed; heatmaps/public feeds named as the targeted use. — [Strava Press](https://press.strava.com/articles/updates-to-stravas-api-agreement); clarification coverage: [Medianama](https://www.medianama.com/2024/11/223-strava-revises-api-rules-to-restrict-data-sharing-and-training-ai-models-using-user-data/)
- CityStrides (a public street-completion map site, closely analogous to the proposed product): on Nov 18, 2024 the developer hid Strava-sourced activities from profiles and public pages; by Jan 31, 2025 users reported Strava activities hidden from other members; users who re-synced via Garmin instead of Strava became visible again (Feb 6, 2025). — [CityStrides community thread](https://community.citystrides.com/t/new-strava-api-terms-dont-allow-sharing-activity-data-to-other-people/28433)
- Intervals.icu forum: the maintainer stated Strava's terms "prohibit showing Strava-sourced activities to followers," that Intervals.icu must delete data if a user disconnects or Strava requests it, and recommended connecting Garmin/Polar/Suunto directly or importing the user's Strava bulk export, which "is not subject to API restrictions." — [Intervals.icu forum, "Strava Privacy Update Nov'24"](https://forum.intervals.icu/t/strava-privacy-update-nov24/79940)
- VeloViewer response: periodic re-confirmation of consent for public sharing, reverting to private otherwise. — [VeloViewer blog](https://blog.veloviewer.com/category/update)
- **June 1, 2026:** subscription requirement for Standard-tier developers (June 30 for existing), intermediary platforms "no longer supported," Club endpoints and Explore Segments deprecated Sept 1, 2026; Strava cited scraping that "degraded platform performance for everyone." — [Strava Community Hub](https://communityhub.strava.com/insider-journal-9/an-update-to-our-developer-program-13428); press: [heise.de](https://heise.de/-11315017)
- **Strava v. Garmin (2025):** filed September 30, 2025 (BikeRadar dates the filing October 2) in federal court in Colorado; alleges infringement of patents covering Segments (filed 2011, granted 2015) and heatmap/"preference map" popularity routing (filed Dec 2014 and 2016) plus breach of the 2015 Master Cooperation Agreement; Strava sought an injunction on much of Garmin's fitness lineup. Strava's CPO tied the timing to Garmin's July 1, 2025 developer guidelines requiring a Garmin logo "on every single activity post, screen, graph, image, sharing card," with a Nov 1, 2025 compliance deadline. On Oct 14, 2025 Strava said it would comply with Garmin's attribution policy; the patent/contract claims were not reported resolved as of mid-October 2025. — [Marathon Handbook](https://marathonhandbook.com/strava-sues-garmin/); [BikeRadar, Oct 3, 2025](https://bikeradar.com/news/strava-explains-why-it-sued-garmin); [the5krunner, Oct 11–14, 2025](https://the5krunner.com/2025/10/11/strava-vs-garmin-its-over/)
- Knock-on: API Policy §4 now requires Garmin attribution in third-party apps: "If your Developer Application displays information derived from Garmin-sourced data, you must display attribution to Garmin in the form and manner required by Garmin's brand guidelines." — [API Policy](https://www.strava.com/legal/api_policy)
- **Heatmap scraping:** no cease-and-desist, DMCA or lawsuit specifically over heatmap-tile scraping was found; enforcement has been technical (403s from March 2018, URL hardening March 2025, outages of community tooling May–Sept 2026). — [OSM Wiki: Strava](https://wiki.openstreetmap.org/wiki/Strava); [OSM-talk Mar 2018](https://lists.openstreetmap.org/pipermail/talk/2018-March/080374.html)

### Inferences
- The two concrete precedents closest to the proposed product — VeloViewer's heatmap tiles and CityStrides' public street maps — were both shut down or forced private by the November 2024 display rule, without any need for Strava to litigate; API-token revocation is the lever.
- The Garmin suit shows Strava asserts patents over heatmap/popularity-map concepts; a third-party "where people run most" layer derived from Strava data would sit squarely inside the IP Strava is actively defending.

### Gaps
- Final disposition of Strava v. Garmin (dismissal/settlement) after October 2025 not confirmed in sources fetched.
- No documented case of Strava issuing a formal legal notice to an individual developer or researcher over heatmap tile use; whether non-OSM academic uses (e.g., published papers using heatmap screenshots) were ever challenged is unknown.
- Elevate (browser extension) impact in 2024 was not confirmed in primary sources; it is mentioned only in general coverage lists.

## Key Question 6: 2025–2026 changes to API agreement, heatmap availability, and Metro

### Takeaway
2025–2026 brought the most restrictive regime in the API's history: a paid-subscription prerequisite (June 1/30, 2026), explicit bans on aggregation, geographic storage, persistent indexes, intermediaries and all AI uses, Explore Segments restricted to Extended Access (Sept 1, 2026), a new ToS (Sept 28, 2026) banning automated collection even when logged in, and Metro Terms (Sept 4, 2026) adding AI bans, tourism tiers and tighter consultant rules. Heatmap product changes since Nov 2024 (Night/Weekly, subscriber-only) were not followed by any 2025–2026 change to Global Heatmap availability that I could find, other than hardened tile URLs.

### Cited Findings
- API Agreement effective June 1, 2026; API Policy effective June 1, 2026 (Policy §1: "Strava may update this Policy from time to time... Your continued use... constitutes acceptance"). — [API Agreement](https://www.strava.com/legal/api); [API Policy](https://www.strava.com/legal/api_policy)
- Timeline from Strava's announcement and changelog: June 1, 2026 two tiers + subscription for new Standard devs + intermediary ban + MCP launch; June 30, 2026 subscription for existing devs; Sept 1, 2026 Club endpoints removed and Explore Segments restricted; Jan 4, 2027 new base URL `api-v3.strava.com`; June 1, 2027 header-only tokens and `oauth/revoke` mandatory (latter per Sahha's reading of Strava's authentication docs). — [Strava Community Hub](https://communityhub.strava.com/insider-journal-9/an-update-to-our-developer-program-13428); [Changelog](https://developers.strava.com/docs/changelog/); [Sahha](https://sahha.ai/blog/strava-api-changes-2026/)
- Strava MCP: "a remote MCP server that gives subscribers conversational access" to their own data; "included with a Strava subscription." — [Strava API FAQ](https://communityhub.strava.com/developers-knowledge-base-14/strava-api-faq-12906); [Community Hub](https://communityhub.strava.com/insider-journal-9/an-update-to-our-developer-program-13428)
- Policy §6.6 preserves the user's own bulk export: "Each Strava user has the right to access and export the user's own Strava data, free of charge, through the Bulk Data Export Tool." — [API Policy](https://www.strava.com/legal/api_policy)
- Policy §5.14 adds compliance with "the regulation of artificial intelligence (including the EU AI Act, where applicable)." — [API Policy](https://www.strava.com/legal/api_policy)
- Terms of Service effective September 28, 2026 add "browser extensions and crawlers" to the automated-access ban and the clause "This prohibition applies regardless of whether you are logged into a Strava account." — [Strava ToS](https://www.strava.com/legal/terms)
- Heatmap: Night and Weekly heatmaps (Nov 13, 2024) are subscriber-only; Global remains for all users. — [Strava Press](https://press.strava.com/articles/strava-expands-mapping-tools-with-night-and-weekly-heatmaps). June 11, 2026 hiking update: subscribers gain "Route Discovery, which surfaces popular paths based on a global heatmap of activity data" — a Strava-internal use of heatmap data, not a new access route. — [Strava Press, hiking features](https://press.strava.com/articles/strava-adds-new-features-for-hiking-making-the-outdoor-experience-more-discoverable-navigable-and-social)
- Heatmap tile access hardened late March 2025; community tooling broken May–Sept 2026. — [OSM Wiki: Strava](https://wiki.openstreetmap.org/wiki/Strava)
- Metro Terms last updated Sept 4, 2026, now including an explicit AI/ML ban, a Tourism Use Case tier with no exports, Counter Data provisions, consultant conditions, and a 2027 academic cohort. — [Metro Terms](https://metro.strava.com/terms); [Metro Academics](https://metro.strava.com/academics)
- Third-party summary of 2026 state for developers: display rules for shared dashboards remain unclear and developers should get written confirmation before relying on any exception. — [Terra blog](https://tryterra.co/blog/strava-api-changes-2026) (secondary)

### Inferences
- Every 2025–2026 change moved in one direction (more restriction, more gating behind subscription/approval). There is no indication of any forthcoming aggregate or heatmap API for third parties; §3.2 explicitly frames "endpoints that expose aggregated user data" as something Strava restricts, not opens.

### Gaps
- I found no Strava announcement in 2025–2026 changing Global Heatmap login/zoom rules; the "Global heatmap available to all users" statement dates from Nov 2024 and I could not re-verify current logged-out zoom behaviour from an official page.
- Whether Strava has published Extended Access acceptance criteria beyond "10,000 users or more" and "qualifying use case" is unknown.
